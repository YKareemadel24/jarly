# Saving Jar engineering audit — Pass 3

11 November 2026 · Flutter source at `43adfea646462a0842355dd606fe8a39912c5b14` on `master`. The app records a single user’s savings locally. The review assumes ordinary single-device use with the possibility of years of history and occasional file or device transfers.

Read [Pass 1](pass-1.md) and [Pass 2](pass-2.md) before reviewing the implementation. Existing A- and B-series findings appear by ID only where they affect a requested classification. The current [Flutter design](../design.md) governs current behavior. The deleted [original design specification](https://github.com/YKareemadel24/jarly/blob/bd64169a372919234ad66b4087a58a201dfb8a73/Saving_Jar_DESIGN.md#L36) supplies the explicit MVP list, exclusions, and detailed accessibility criteria.

Verification used source and locked dependency inspection, a location-only Git scan, contrast calculations, PNG header measurements, and six Flutter widget probes with synthetic data and host fonts. “Confirmed” below identifies an observed data path or defect. OS effects inferred from code or platform contracts are marked as such.

## 1. Security and privacy

### Confirmed vulnerabilities and disclosures

1. **High — A GitHub credential was recorded in local Git history.** Location only: `9209c5f:.codex/config.toml:5`, `1b4c5c2:.codex/config.toml:5`, and `62f36dc:.codex/config.toml:5`. These revisions are reachable through local stash or tooling refs. Ancestry checks against both `HEAD` and the locally recorded `origin/master` returned false, and the file is absent from both tips. The authorization field contains a token matching the fine-grained GitHub credential format. Validity, privileges, and publication through any other ref or remote remain unknown. Revoke the credential and check its usage with the owner. Move the configuration to an environment-backed credential after rotation.

2. **High — The app lock leaves private savings data in the accessibility tree.** A widget probe mounted the production app root with PIN lock enabled and a synthetic funded jar. While the visible PIN gate remained in place, Flutter semantics still exposed the underlying jar label with its name, percentage, saved amount, and target. The router remains mounted beneath a painted `Positioned.fill` overlay. Hardware screen-reader behavior and keyboard activation beneath this gate were unverified. Exclude the underlying app from semantics and focus while locked, and assert that a funded jar is absent from the semantics tree until unlock. [App stack](../lib/app.dart#L44), [lock overlay](../lib/ui/screens/lock_gate.dart#L241), [jar card label](../lib/ui/screens/home_screen.dart#L644).

3. **Medium — Device transfer sends archived financial history omitted from its disclosure.** The hub and Send screen count active jars only. The shared exporter serializes the entire local jar list, including archived jars and their history, into the QR and shared text. A store containing only archived jars can report that there are no jars to move while generating frames with those records. This is confirmed by tracing the payload, and exposure requires the user to show or share the codes. Make the count and disclosure describe the exact snapshot used to create the frames. Keep the documented full-history file backup behavior. [Hub count](../lib/ui/screens/transfer_hub_screen.dart#L31), [Send copy and frame creation](../lib/ui/screens/transfer_send_screen.dart#L40), [Send count](../lib/ui/screens/transfer_send_screen.dart#L126), [snapshot exporter](../lib/state/savings_controller.dart#L353), [wire encoding](../lib/transfer/transfer.dart#L135).

**Verdict.** Revoke the historical credential, close the lock’s accessibility exposure, and make device transfer disclose every included record. The remaining release checks with fresh evidence are iOS permission timing, Back behavior, and the documented accessibility failures. Bank linking, automated purchase round-ups, group-jar functionality and investment-return features are absent from the executable. Transfer’s group-jar wording is the exception in user-facing scope.

**Verification limits.** No physical mobile device, signed build, native assistive technology, app-switcher capture, force-kill, OS notification delivery, or live dependency sweep was available. The widget probes establish the reported Flutter behavior under synthetic conditions. The temporary probe was removed after verification.
