# Saving Jar — engineering audit, pass 2

**What this repo does.** Saving Jar records savings goals, habits and transactions in a local Flutter app. This review assumes one person using one app instance, with overlapping callbacks and asynchronous writes possible during ordinary use.

**Scope and evidence.** Reviewed `4d134fc4185550a86c5210697c01d5ee5c0c6efc` on `master` on 2026-11-11 (Africa/Cairo). A01–A20 refer to the local [Pass 1 report](pass-1.md). This pass reran `flutter test --no-pub --reporter expanded` and all 166 existing tests passed. The flow trace uses source inspection and identifies runtime evidence carried over from Pass 1. New cases below are source-derived unless explicitly attributed to an existing probe. Native hardware, interrupted disk writes, browser offline startup, and live accessibility and theme behavior were outside this pass's runtime checks.

## 3. Architecture and concrete findings

The primary ownership boundaries are useful. Routes keep drafts, `SavingsController` owns the jar list, and pure functions calculate ledger changes and projections. UI code does not call the key/value store directly. The settings repository also exports preference data used by the UI, and `SettingsController` owns the platform auth call. In tests, the latter requires a plugin seam or channel fake because it constructs the platform client directly. `storageProvider` already supports injection, so controller tests can exercise real domain and persistence code without another data layer. [`providers.dart:14`](../lib/state/providers.dart#L14), [`savings_controller.dart:142`](../lib/state/savings_controller.dart#L142), [`settings_controller.dart:95`](../lib/state/settings_controller.dart#L95), [`settings_controller.dart:269`](../lib/state/settings_controller.dart#L269)

Jar, entry and state fields are `final`, but their list references are mutable. Normal mutation paths replace lists and the review found no UI caller mutating a published list in place. That keeps this an ownership constraint for future changes. The large detail widget becomes costly where one `build` function owns form state, validation and ordering for multiple mutations. B06 is an example where a dismissal path leaks draft data across forms. Whole-list snapshot writes and repeated ledger scans scale with history length. Existing evidence does not establish a performance bottleneck at the expected single-user load. [`jar.dart:173`](../lib/domain/jar.dart#L173), [`jar.dart:314`](../lib/domain/jar.dart#L314), [`savings_controller.dart:106`](../lib/state/savings_controller.dart#L106), [`jar_detail_screen.dart:81`](../lib/ui/screens/jar_detail_screen.dart#L81), [`savings_storage.dart:103`](../lib/data/savings_storage.dart#L103)

### Must fix

**B01 — Amount input can silently change an ordinary pasted amount.** The formatter treats the first comma as a decimal point and drops extra separators and fractional digits. Pasting `1,234.56` produces `1.23` and the same app formats money with grouping commas. A pasted minus is discarded, too. A user can confirm a valid-looking amount that differs materially from the input in create, deposit, withdrawal or target/recurring edit. Keep one shared money-entry policy and reject ambiguous or signed inputs with guidance, or parse grouped values unambiguously. A01 covers a separate precision boundary. [`money.dart:75`](../lib/domain/money.dart#L75), [`jar_detail_screen.dart:1050`](../lib/ui/screens/jar_detail_screen.dart#L1050), [`new_jar_screen.dart:740`](../lib/ui/screens/new_jar_screen.dart#L740), [`money_test.dart:38`](../test/money_test.dart#L38)

**B02 — Local restart accepts a balance that contradicts its saved ledger.** A v3 jar with `openingBalance: 0`, `balance: 500` and a single 100-minor withdrawal at a valid date satisfies the field and audit-link checks. The ledger replayer rejects it because the opening balance reconstructed from that history is 600. Home and history can therefore present contradictory values while correction/transfer rejects the record, and the persister considers the current snapshot backup-worthy. Reuse the ledger invariant in current-snapshot validation and preserve the documented opening-balance behavior for legacy data. [`savings_storage.dart:25`](../lib/data/savings_storage.dart#L25), [`savings_storage.dart:51`](../lib/data/savings_storage.dart#L51), [`savings_storage.dart:103`](../lib/data/savings_storage.dart#L103), [`transactions.dart:103`](../lib/domain/transactions.dart#L103), [`merge.dart:107`](../lib/transfer/merge.dart#L107)

**B03 — An invalid persisted cadence can generate 366 deposits for one occurrence.** A due rule with a positive safe amount and an unsupported cadence passes the stored-jar validator. The scheduling switch returns the same date, so each loop iteration writes another entry at that time until the cap. This requires malformed or incompatible stored data. An ordinary editor choice cannot produce it. Validate cadence and optional date at hydration, and stop a rule whose cursor does not advance. The transfer validator already checks the cadence. [`jar.dart:650`](../lib/domain/jar.dart#L650), [`savings_storage.dart:68`](../lib/data/savings_storage.dart#L68), [`schedule.dart:12`](../lib/domain/schedule.dart#L12), [`schedule.dart:63`](../lib/domain/schedule.dart#L63), [`transfer.dart:350`](../lib/transfer/transfer.dart#L350)

**B04 — The global storage warning has invalid `Positioned` ancestry.** When `storageError` is set, `StorageWarning` puts `Semantics` between `Stack` and `Positioned`. Flutter requires the positioned child to set layout data on a Stack child, and `Semantics` inserts a render object in between. That path can produce an incorrect-parent-data error instead of a reliable alert when saving or loading fails. Put `Positioned` outside the semantics wrapper and verify the real app root with a failed read and write. A02's controller probe observed warning state, which leaves this widget path untested. [`app.dart:46`](../lib/app.dart#L46), [`storage_warning.dart:15`](../lib/ui/widgets/storage_warning.dart#L15), [Pass 1 persistence probes](persistence_probes_test.dart)

An archived jar with a due rule can show a larger balance in Profile after reopening and bring new history back when restored. A later unrelated save can persist those entries. ### False confidence in specific tests

- **The overlapping-write test bypasses the shared queue.** It calls `JarsPersister()` separately for `older` and `newer`, then asserts only the final current balance. A broken serialization mechanism can pass depending on completion order. One instance, a blocked first write, an assertion that the second has not begun, and final current/backup checks would exercise production behavior. [`savings_storage_test.dart:46`](../test/savings_storage_test.dart#L46)
- **Test names claim more than the assertions.** “Rejects unsafe or fractional money” sends only `1.5` and never exercises an out-of-range native integer (A08). “Never touches milestones” has no hit levels in its withdrawal fixture. “Counts one milestone per deposit” actually asserts two crossed levels on the second deposit and does not invoke the controller's highest-level choice. [`transfer_test.dart:44`](../test/transfer_test.dart#L44), [`jar_test.dart:30`](../test/jar_test.dart#L30), [`jar_test.dart:54`](../test/jar_test.dart#L54)
- **Self-round-trips verify compatibility weakly.** The legacy tuple padding test encodes and decodes using the same implementation and only checks prefix/source/note. Matching encoder and decoder regressions can pass. An independently captured RN-produced frame and a fixed tuple assertion would check the wire contract. Other transfer tests do use hand-built payloads for negative cases. [`transfer_test.dart:44`](../test/transfer_test.dart#L44), [`transfer_test.dart:203`](../test/transfer_test.dart#L203)
- **DST labels do not guarantee a transition.** Calendar wall-time expectations are meaningful, but the elapsed-time expectation derives its offset delta from the returned dates. It also passes on a host without a transition at those timestamps. Set a known DST zone or assert a known nonzero offset transition. [`reminder_test.dart:123`](../test/reminder_test.dart#L123), [`reminder_test.dart:162`](../test/reminder_test.dart#L162)
- **Render-only, no-exception-only, over-mocking and duplicated logic.** There are no render-only widget tests. Most cases assert returned values or expected rejection, and the small storage fakes sit at the I/O boundary. No broad pattern of over-mocking or reimplementing business logic was found. The accent-list smoke assertion covers key presence and a `#` prefix, which leaves rendered contrast and theme behavior unmeasured. [`money_test.dart:42`](../test/money_test.dart#L42), [`savings_storage_test.dart:118`](../test/savings_storage_test.dart#L118)

### Ten most valuable missing tests, in priority order

1. **Financial commit and recovery through the real controller and app root.** Block and fail the storage write after a deposit/withdrawal. Assert the correct pending/error state and a visible, accessible warning. Require no success haptic, toast or celebration before persistence. Then retry and recreate the provider container against the same store. Assert one signed entry, the right balance and preserved milestones. A02, B04.
2. **One confirmation produces one mutation.** Invoke the same rendered callback twice before the next frame for deposit, withdrawal and first-jar creation. Assert exactly one mutation of the intended direction/ID, one acknowledgement and the same result after reload. A04.
3. **Exact amounts through all editors.** Drive plain two-decimal values, grouped paste, signed paste and adjacent cents near the supported bound through wizard, money sheet and correction. Assert displayed/committed minor units match the accepted amount, with an explicit rejection for unsupported input. Assert note-only edits preserve stored money. A01, B01.
4. **Startup, foreground and repeated restart for recurring.** Seed due, paused and archived rules. Exercise real hydration, resume twice and reopen using one store. Assert exactly-once occurrence IDs, saved cursor, archive policy and stable balance. Change daily/weekly/biweekly/monthly through the editor and verify the persisted selection and date. A05, A13, A15, B05.
5. **App lock across storage failures and lifecycle.** Cover failed storage initialization, PIN flag and credential failure at each enable/disable step, then rebuild settings and gate from the same store. Assert accessible fail-closed feedback, recoverability and consistent lock policy. A03, A06.
6. **Stored ledger and rule validation, plus real migration.** Use v1/v2 fixtures, a valid v3 backup, a contradictory ledger and a due invalid cadence. Assert fallback precedence, unchanged corrupt input, no generated entries for rejected rules, exact migrated cents, stable IDs and one v3 reload after write. B02, B03.
7. **Financial milestone lifecycle.** Assert one cent below/at/above each threshold, a multi-level jump, small targets that need a ceiling, and a completed jar withdrawn below target and funded again. Check stored hit levels, exact quick preset, highest-only modal and no repeat on restart. A18, B11.
8. **End-to-end correction, Undo and projections across local dates.** Correct date/amount, reject an unfunded historical withdrawal, reverse once, then reopen. Assert revisions, current balance, Activity order/filter and Insights counts/month buckets in a known timezone across midnight or a DST transition. Verify the newest Undo toast gets its full display interval. A17, B10.
9. **Create/edit/archive lifecycle and read-state UI.** Reject invalid name/target/deadline, preserve data on Cancel, and verify archive, restore and confirmed deletion across reload. Hold a valid detail deep link pending, then exercise true missing ID, genuine empty Home and a read failure. A14, A16, B07, B08.
10. **Accessible, reduced-motion theme and settings interactions.** Activate the primary flow using keyboard and semantic actions, assert focused modal and announced errors, then enable reduced motion and check key transitions. Switch Light/Dark/System with a simulated OS brightness change, failed preference save and restart. Assert Material, custom palette and selected control agree. A11, B09.
